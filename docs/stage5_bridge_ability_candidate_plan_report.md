## 一、为什么桥梁能力节点不能替代硬知识节点

### 1.1 维度不同

| 类型 | 维度 | 示例 |
|:-----|:-----|:-----|
| **硬知识节点** | 算法/数据结构/数学知识本身 | "线段树的原理和实现"、"Dijkstra最短路算法" |
| **桥梁能力节点** | 连接知识与题目的思维方法 | "看到区间查询想到什么"、"如何从暴力发现DP" |

硬知识节点回答"这个算法是什么、怎么实现"，桥梁能力节点回答"什么时候用这个算法、怎么想到用这个算法"。

### 1.2 学习阶段不同

```
学习路径：
  硬知识学习 → 桥梁能力训练 → 实战应用
  
示例：
  学会线段树（硬知识）
      ↓
  学会"看到区间查询想到线段树"（桥梁能力）
      ↓
  在比赛中正确识别并应用线段树（实战）
```

学生可能已经学会了线段树的原理和实现（硬知识），但看到题目时不知道这题可以用线段树（桥梁能力缺失）。

### 1.3 不可替代性

桥梁能力节点**不能**替代硬知识节点，因为：
- 没有硬知识，桥梁能力无从谈起
- 桥梁能力是"如何运用知识"，不是"知识本身"
- 两者是互补关系，不是替代关系

## 二、为什么桥梁能力节点也必须纳入图谱

### 2.1 学生的真实痛点

| 痛点 | 桥梁能力节点解决 |
|:-----|:-----------------|
| "懂原理但写不出代码" | 代码实现技巧节点 |
| "从题目想不到算法" | 解题分析方法节点 |
| "坚持不下来、比赛发挥失常" | 训练管理节点 |

这些痛点**无法通过增加更多硬知识节点解决**，需要专门的桥梁能力节点。

### 2.2 系统化学习需求

当前桥梁能力相关内容：
- 散落在各处（5.2代码技巧、5.3读题技巧、5.11竞赛心理）
- 不系统、不完整
- 学生难以系统学习

纳入图谱后：
- 可以有完整的分类结构
- 可以有前置依赖关系
- 可以有学习路径规划

### 2.3 产品价值

| 产品功能 | 需要桥梁能力节点 |
|:---------|:----------------:|
| 学习路径推荐 | ✅ |
| 薄弱点诊断 | ✅ |
| 题目关联推荐 | ✅ |
| 训练计划生成 | ✅ |

### 6.2 生成流程

```
1. 基于样例模板批量生成候选
2. 对每个候选：
   - 检查与主图谱已有节点的重复
   - 设置 risk_band
   - 设置 mapping_confidence
3. 输出完整候选池 JSON
4. 人工审核 yellow/medium 风险候选
5. 分批合并到主图谱
```
