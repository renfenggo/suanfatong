## 三、代码实现技巧

> 建议扩充：**约 600 个**
>
> 说明：解决学生"懂原理但写不出代码"的问题，包括变量设计、边界处理、循环写法、模板改造、调试方法等。

### 当前基线

C++编程/调试技巧当前 **123 节点**，11 个 Section。
偏重调试（21 节点）、常见错误（15 节点）、代码技巧（17 节点）等。
但**代码实现过程**本身缺少系统化拆解。

### 建议扩充方向

#### 3.1 变量与状态设计（建议 +60～70）

- **变量命名与含义规划**：写代码前先定义变量含义
- **状态表示选择**：用 int / bool / struct / enum 的决策依据
- **全局变量 vs 局部变量**：作用域设计、避免状态污染
- **中间变量命名**：tmp / cur / nxt / pre 等临时变量的规范使用
- **常量与魔数处理**：const / constexpr / #define 的合适场景

#### 3.2 边界处理专项（建议 +60～70）

- **数组越界的典型场景**：下标从 0 还是从 1、开大一点
- **二分边界检查表**：`l < r` vs `l <= r`、mid 取法、死循环排查
- **循环边界判断**：`i < n` vs `i <= n`、`i + k < n` vs `i <= n - k`
- **空集合 / 单元素 / 全相同**：特殊边界测试思维
- **整数溢出防护**：`int` vs `long long`、乘法的溢出判断、中间结果类型

#### 3.3 循环与迭代模式（建议 +50～60）

- **循环不变式**：每次循环开始时确保的条件
- **多层循环的变量管理**：内层循环变量重置、break/continue 的行为确认
- **迭代器失效**：vector 插入删除时的迭代器问题
- **遍历模式的标准化写法**：for-range、下标遍历、迭代器遍历的选用
- **递归 vs 迭代转换**：手动栈模拟、尾递归优化、深度限制预防

#### 3.4 常用算法模板化实现（建议 +80～100）

- **图论模板结构**：邻接表初始化、加边、遍历的统一风格
- **DP 数组维度与转移顺序**：外层循环物品、内层循环容量等传统写法
- **二分查找标准模板**：`lower_bound` / `upper_bound` 的实现细节
- **并查集模板**：路径压缩 + 按秩合并的标准写法
- **线段树模板化**：build / update / query 的统一接口
- **最短路模板**：Dijkstra（堆优化）、SPFA（负环检测）、Floyd（注意顺序）
- **快速幂 / 矩阵快速幂模板**：泛型化、取模规范
- **输入输出模板**：`ios::sync_with_stdio(false)`、快读快写

#### 3.5 调试与验证方法（当前已有 21 节点，建议 +40～50）

- **print 调试技巧**：关键变量输出、分段输出、条件输出
- **对拍自动化**：暴力 vs 优化版的对拍脚本
- **断言式调试**：`assert()` 的合理用法
- **小数据测试**：手动构造小样例、边界样例、随机样例
- **调试信息分级**：info / warn / debug 的分层输出
- **gdb / lldb 命令行调试**：断点 / 观察点 / 调用栈

#### 3.6 代码错误模式库（当前已有 15 节点，建议 +40～50）

- **初始化遗漏**：多组数据时忘记重置数组/变量
- **类型转换错误**：隐式转换、截断、符号扩展
- **比较运算符错误**：`=` vs `==`、浮点数比较用 epsilon
- **逻辑短路误判**：`&&` 和 `||` 的短路行为带来的副作用
- **数组长度计算错误**：`sizeof(a)/sizeof(a[0])` vs `a.size()`
- ** string 与 char\* 混用**：C 风格字符串的陷阱

#### 3.7 代码优化工程（当前 5.10 仅 3 节点，建议 +40～50）

- **常数优化分类**：IO 优化、内存布局优化、循环展开
- **编译优化**：`-O2` 的效果、`__builtin` 函数的使用
- **内存优化**：`vector::reserve`、避免不必要拷贝、移动语义
- **时间换空间**：预处理打表、离线查询、空间压缩
- **空间换时间**：预计算、缓存、哈希加速

#### 3.8 代码风格与组织（当前 5.2 部分覆盖，建议 +40～50）

- **函数拆分粒度**：何时该抽取子函数、回调函数设计
- **结构体 vs 类**：POD 类型用 struct、带方法的用 class
- **命名空间管理**：避免命名冲突、匿名 namespace
- **错误处理**：返回值和异常处理的选择
- **代码可读性与可维护性**：注释哪些、不注释哪些、代码格式化

#### 3.9 数据类型选择进阶（当前 1.3 部分覆盖，建议 +40～50）

- **何时用 `int64_t` / `uint64_t` / `__int128`**
- **浮点数精度管理**：float / double / long double 的选择
- **模运算中的数据类型**：乘法的取模中间结果跨越
- **位宽感知编码**：避免因类型宽度不一致导致的 bug
- **自定义类型**：重载运算符、自定义比较器、哈希特化

#### 3.10 多文件与工程化（建议 +30～40）

- **版本管理**：本地修改与竞赛模板的版本协调
- **构建与编译**：Makefile 基础、多个 .cpp 文件的编译

> **小计**：代码实现技巧建议扩充约 600 个。

## 四、解题分析方法

> 建议扩充：**约 500 个**
>
> 说明：解决学生"从题目想不到算法"的问题，包括造样例、找规律、数据范围分析、排除错误做法、从暴力到优化等。

### 当前基线

当前图谱**没有**独立的解题分析分类。
少量相关节点散落在 2.1（基础算法思想）和 5.3（读题技巧）中，不系统。

解题分析是介于"看到题目"和"知道用什么算法"之间的思维方法，与算法知识本身是不同维度的能力。需要一个**独立的大分类**来承载。

### 建议扩充方向

#### 4.1 读题与分析（建议 +60～70）

- **题目结构化阅读**：提取输入、输出、约束、样例含义
- **关键条件提取**：从题目描述中识别限制条件和特殊性质
- **样例推演**：从输出反推题目意图、用样例验证理解是否正确
- **数据范围预判**：根据 n=10^5 推断 O(n log n)、n=20 推断状压
- **时间限制解读**：1s 对应的大致运算量、CPU 感知

#### 4.2 分类思考框架（建议 +80～100）

- **"这是什么类型的问题"**：最值 / 计数 / 判定 / 构造 / 交互
- **最值问题的思考路径**：贪心？DP？二分判定？网络流？
- **计数问题的思考路径**：组合公式？递推？DP？容斥？
- **判定问题的思考路径**：二分 + 验证？构造性判定？
- **构造问题的思考路径**：有无规律？奇偶性？归纳构造？图论构造？
- **从约束类型反推算法**：无后效性→DP、交换论证→贪心、子问题重叠→DP

#### 4.3 从暴力到优化（建议 +80～100）

- **先写暴力再优化**：暴力枚举的正确性验证、暴力作为正确性基准
- **暴力到二分优化**：枚举 → 单调性发现 → 二分
- **暴力到数据结构优化**：前缀和、差分、线段树优化枚举
- **暴力到 DP**：暴力搜索 → 重叠子问题发现 → 状态定义
- **暴力到数学优化**：发现数学规律代替枚举
- **复杂度演进意识**：O(n^2) → O(n log n) → O(n) 的典型路径

#### 4.4 错误做法排除（建议 +50～60）

- **"为什么这题不能用贪心"**：反例构造方法
- **"为什么我的 DP 状态不对"**：最优子结构验证、后效性检查
- **"这个算法理论上可行吗"**：复杂度估算、极端情况测试
- **常见错误直觉**：看到序列就排序、看到图就最短路
- **反例构造能力**：最小反例、边界反例、随机反例

#### 4.5 特殊方法集合（建议 +50～60）

- **构造性证明转化为代码**：结构归纳、贪心构造
- **巧算与技巧**：利用对称性、奇偶性、模性质简化问题
- **观察法解题**：找规律、猜结论、验证猜想
- **特殊情况启发**：简化条件、从特殊到一般
- **换角度思考**：补集转化、正难则反、对偶问题

#### 4.6 常见题型思维链（建议 +80～100）

- **"看到区间查询想到什么"**：前缀和、线段树、树状数组、ST 表
- **"看到最大值最小化想到什么"**：二分答案 + 贪心验证
- **"看到路径计数想到什么"**：DP、组合数、矩阵快速幂
- **"看到子串/子序列想到什么"**：双指针、DP、字符串算法
- **"看到图论判定想到什么"**：并查集、BFS/DFS、二分图染色
- **"看到方案数取模想到什么"**：DP + 组合数学、容斥、生成函数

#### 4.7 赛后复盘方法（建议 +30～40）

- **补题时机选择**：刚考完 vs 隔天复现 vs 专题回顾
- **错因分析框架**：审题错 / 思路错 / 实现错 / 边界错
- **不看题解自己推理**：从题目条件出发的独立推导训练
- **一题多解记录**：每种方法的优缺点和适用条件
- **解题笔记模板**：题目链接、思路过程、关键点、代码链接

> **小计**：解题分析方法建议扩充约 500 个。

## 五、训练管理与竞赛心理

> 建议扩充：**约 400 个**
> 
> 说明：解决学生"坚持不下去、训练没节奏、比赛发挥不稳"的问题，包括时间分配、自律、错题复盘、挫败应对、比赛策略等。
> 
> **语气说明**：本分类的节点描述应像关心算法学习者的朋友。先承认困难，再给建议。不用训话语气，不煽情打鸡血，不绝对化表达（不说"必须""一定""绝对不能""永远"）。优先用"可以试试""通常会更稳""先做一个小动作"这类表达。

### 当前基线

当前图谱仅 **5.11（算法竞赛心理与策略）** 三个占位节点。
训练管理和竞赛心理是**完全空白**的大分类。

### 建议扩充方向

#### 5.1 长期训练节奏（建议 +40～50）

- **学期训练节奏怎么定**：如果一周能抽出 5～8 小时，可以试试固定两段训练时间
- **假期怎么不荒废**：每天做一道题比周末刷十道题更容易坚持
- **训练量过大的信号**：如果连续几天看到题目就烦，可以试试停一两天
- **训练分级**：舒适区练习巩固信心、学习区练新知识、困难区偶尔挑战
- **训练日志怎么写**：不用长篇大论，记三行——今天练了什么、卡在哪里、明天打算
- **周/月度回顾怎么做**：翻翻训练日志，看看哪些类型的题经常卡住，通常比直接刷题更有收获

#### 5.2 日常练习方法（建议 +40～50）

- **刷题不追求数量**：一道题彻底弄懂，比乱刷十道更有用
- **卡题多久该看题解**：可以给自己设个时间，比如 30 分钟没进展就看一眼思路提示
- **看题解的正确方式**：看思路不看代码，然后自己重新写
- **专题练习 vs 随机练习**：学新知识时按专题练，巩固时随机抽题效果更好
- **难度怎么选**：比自己当前水平略高一点的题，通常成长最快
- **重复练习的意义**：过一段时间重新做做过的题，看看能不能更快更稳

#### 5.3 错题与复盘机制（建议 +40～50）

- **错题本怎么记才有用**：不是贴代码，而是记当时为什么想错了
- **常见错误模式识别**：如果经常在同一个地方出错，可以写个小检查清单
- **赛后复盘要做什么**：趁还记得思路过程，先把当时怎么想的写下来，再对比标解
- **"这道题我原本可以 AC" 类复盘**：把丢分原因分成审题、思路、实现、边界四类
- **复现练习**：隔一周重新做错过的题，看看是不是真的弄懂了
- **从错题中发现薄弱专题**：如果某个知识点反复出错，说明需要回头补基础

#### 5.4 自律与坚持（建议 +30～40）

- **学不动了怎么办**：可以先做个简单的、或者先休息，不用勉强
- **如何建立小习惯**："每天打开题库做一道题"比"每天刷三小时"更容易坚持
- **阶段性目标设定**：可以试试每个月设一个小目标，比如"这月 AC 15 道以前不会的题"
- **训练伙伴的作用**：找一个人一起练，互相出题或者互相 review 代码，效果通常好过自己闷头练
- **接受平台期**：水平提升不是线性的，有时候一两个月感觉没进步也是正常的

#### 5.5 竞赛策略与时间管理（建议 +40～50）

- **比赛时间怎么分配**：先通读所有题，评估每道题的难度，再决定先做哪道
- **卡题了要不要换**：如果一道题想了 20～30 分钟没有进展，可以试试先做别的
- **暴力先拿分**：在正解不确定的时候，先写暴力/部分分通常是稳的选择
- **难度判断能力**：读题后快速评估"这题大概是什么难度"，决定投入多少时间
- **剩余时间的策略**：最后 30 分钟适合检查代码、修 bug、写暴力，不适合开新题
- **多组测试数据的处理**：正式比赛时每组数据都测一遍样例再提交

#### 5.6 赛前准备与心理调节（建议 +40～50）

- **赛前一周怎么练**：不用学新东西，做做已经会了的题保持手感就够了
- **赛前休息**：比赛的发挥上限很大程度上取决于比赛前一晚的睡眠质量
- **进场后的前五分钟**：深呼吸、写模板头文件、调整心态，不用急着看题
- **比赛中出现低级错误怎么办**：谁都出过，先继续做后面的，回来再改就行
- **如何处理紧张**：如果心跳很快，可以先做一道简单题进入状态
- **考后情绪管理**：没考好可以试试先不看任何题解，过两天再平静地复盘

#### 5.7 挫败应对与心态修复（建议 +30～40）

- **零题选手的心理建设**：每个人都有"一题都没做出来"的时候，这不代表不适合这条路
- **为什么别人进步比我快**：每个人的起点和时间投入不一样，重要的是自己有没有在往前走
- **不想碰那道卡了很久的题**：可以先放一放，过几天再看，有时候需要时间消化
- **竞赛成绩不如预期**：可以试试把"学到什么"放在"排名多少"前面
- **怎么从挫败中恢复**：先做几道简单题重建信心，再回头分析失败原因
- **承认有些知识点目前还啃不动**：暂时放一放，等基础更扎实了再回来，通常效果更好

#### 5.8 信息管理与环境搭建（建议 +30～40）

- **题单管理系统**：可以用简单的分类法——已 AC、已理解未 AC、卡住、待做
- **常用资料整理**：把模板、笔记、好题按专题分类，方便赛前快速翻
- **本地编辑器/IDE 配置**：代码补全、格式化、快捷编译的配置对比赛有帮助
- **网络资源筛选**：好的博客、题库、题解平台各有哪些特点和适用场景
- **灵感记录习惯**：做题过程中突然想到的思路，随手记下来

#### 5.9 目标规划与长期成长（建议 +30～40）

- **从入门到竞赛的路径规划**：不同阶段应该重点练什么
- **如何选择竞赛目标**：省赛 / 区域赛 / NOI / ICPC——不同目标对知识面的要求不一样
- **如何判断自己是否准备好进入下一阶段**：如果在当前阶段的大部分题目能在合理时间内做出来，就可以试试挑战更难的
- **学习资源迭代**：不同阶段适合不同的书/题库/教程，定期评估正在用的资源是否还合适
- **与教练/队友的有效沟通**：主动描述自己卡在哪里，比只说"不会"更能获得有效帮助

> **小计**：训练管理与竞赛心理建议扩充约 400 个。

### 重要原则

#### 原则一：硬知识与桥梁能力分开

- **算法与数据结构 + 竞赛数学**属于**硬知识节点**，约 1,200 个左右的扩充量，必须独立保留。
- **代码实现**、**解题分析**、**训练管理与竞赛心理**属于**桥梁能力节点**，不能替代硬知识节点。
- 桥梁能力解决的不是"知道什么算法"，而是"怎么想到""怎么写出来""怎么坚持练下去"。

#### 原则二：总量规划

- 当前 2,165 个知识点，长期可规划到 **4,500～5,000 个**左右。
- 建议分阶段实施，每阶段 300～500 个，保证每个新增节点都经过查重和依赖校验。

#### 原则三：不凑数量

- 扩充原则不是凑数量，而是补齐学习价值。
- 每个候选节点必须满足：**当前图谱中没有相同或等效概念**，且**对学生学习路径有实际帮助**。
- 避免为扩充而扩充——如果一个主题能用已有节点组合表达，就不用新增。

#### 原则四：所有候选查重

- 所有正式候选节点在实施前，必须基于 **2,165 个已有节点**做全图谱查重。
- 查重范围包括：`item.name`、`item.alias`、`section_id`、`parent`。
- 查重通过的候选节点，还要做依赖完整性检查和循环依赖检测。
